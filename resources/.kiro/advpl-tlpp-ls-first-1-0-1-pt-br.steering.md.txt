# AdvPL/TLPP — navegação LS-first e encoding de gravação

Esta disciplina é ativada quando fontes AdvPL/TLPP estão no contexto. Ela se aplica a tarefas de navegação, análise, criação, correção e refatoração.

## Sequência semântica obrigatória

Antes de busca textual ou leitura manual, use o Language Server nesta ordem:

1. `lsp_workspace_symbols` — localizar o símbolo.
2. `lsp_definition` — confirmar sua definição.
3. `lsp_references` — mapear usos e impacto.

A primeira ação de investigação deve usar uma ferramenta do Language Server. Não comece com `grep_search`, `file_search`, `read_file` ou leitura manual quando houver cobertura semântica disponível.

## Exceção controlada

Use busca textual ou leitura manual somente quando o Language Server estiver indisponível, falhar, não localizar o símbolo ou não oferecer cobertura para o arquivo. Antes de prosseguir, registre explicitamente:

> LS indisponível/sem cobertura; prosseguindo com busca textual.

Depois de localizar o código, valide APIs, assinaturas e metadados Protheus nos MCPs oficiais aplicáveis, conforme o `AGENTS.md`.

## Encoding obrigatório na gravação (Windows-1252 / Windows-1251)

As ferramentas de escrita do agente (`fs_write`, `str_replace`, `fs_append`) gravam o texto em **UTF-8** e **não** aplicam o `files.encoding` do `.vscode/settings.json`. O compilador Protheus só aceita fontes no codepage do ambiente; UTF-8 corrompe strings acentuadas, altera `Len()`/`SubStr()` e gera erro de compilação (SonarQube CA0000).

Portanto, **todo** arquivo AdvPL/TLPP criado ou alterado pelo agente deve terminar gravado em disco no codepage abaixo. Não existe exceção.

| Ambiente | Codepage obrigatório | Nome no `iconv` | Equivalente VS Code |
| --- | --- | --- | --- |
| Padrão (Brasil e demais localizações) | **Windows-1252** | `CP1252` | `"files.encoding": "windows1252"` |
| Russo (localização Rússia) | **Windows-1251** | `CP1251` | `"files.encoding": "windows1251"` |

### Como decidir o codepage (nesta ordem)

1. **Arquivo existente:** preserve o codepage que ele já tem. Nunca troque um fonte existente de 1252 para 1251 (ou o contrário). O comando `file --mime-encoding` reporta `iso-8859-1`/`unknown-8bit` para ambos, então ele só distingue UTF-8 de não-UTF-8. Para separar 1252 de 1251, decodifique uma linha de comentário dos dois jeitos (`iconv -f CP1252 -t UTF-8` e `iconv -f CP1251 -t UTF-8`) e use o que produzir texto legível (português × russo).
2. **Configuração da workspace:** `files.encoding` (global ou no escopo da linguagem, ex.: `"[advpl]"`) no `.vscode/settings.json`. `windows1251` indica ambiente russo; `windows1252` indica o padrão.
3. **Declaração do usuário ou da tarefa:** o usuário informa que o ambiente é russo ou que a tarefa é da localização Rússia.
4. **Sem nenhuma indicação:** use **Windows-1252**.

Se as fontes acima entrarem em conflito (ex.: tarefa russa, mas `settings.json` com `windows1252`), pare e pergunte ao usuário antes de gravar.

### Shell a usar por sistema operacional

- **Linux/macOS:** Bash + `iconv` (comandos `bash` abaixo).
- **Windows:** tente primeiro o **PowerShell**. Se ele não funcionar, use o **CMD (`.bat`)**. Considere que o PowerShell "não funcionou" quando:
  - o `.ps1` é bloqueado pela política de execução (`running scripts is disabled on this system` / `execução de scripts foi desabilitada`);
  - `powershell` não é reconhecido no terminal, ou o terminal do agente é o CMD;
  - o comando falha por erro do próprio PowerShell (perfil, host, sintaxe), não por erro do arquivo.

  Os comandos CMD abaixo chamam o `powershell.exe` inline com `-Command` a partir do `cmd`, o que não depende da política de execução de `.ps1`. Se nem o `powershell.exe` existir, use o `iconv.exe` do Git for Windows (`"C:\Program Files\Git\usr\bin\iconv.exe"`) ou os comandos `bash` no Git Bash. Se nenhum caminho funcionar, **pare e avise o usuário**: não deixe o fonte em UTF-8.

Registre na evidência de conformidade qual caminho foi usado (PowerShell, CMD ou fallback).

### Fluxo obrigatório

**Arquivo novo ou reescrita completa** — escreva com a ferramenta normalmente e, em seguida, converta **in-place** (mesmo nome, mesma extensão, sem BOM):

- **Windows-1252** — use a skill `utf8-to-cp1252-conversion`.

  Linux/macOS:

  ```bash
  bash .kiro/skills/utf8-to-cp1252-conversion/scripts/convert-encoding.sh "<arquivo>"
  ```

  Windows: a skill entrega o script como `.bat` (não há `.ps1`) e proíbe conversão manual, então use sempre o `.bat`. No PowerShell, chame-o com `&`:

  ```powershell
  & .kiro\skills\utf8-to-cp1252-conversion\scripts\convert-encoding.bat "<arquivo>"
  ```

  Se o PowerShell não funcionar, rode no CMD:

  ```cmd
  .kiro\skills\utf8-to-cp1252-conversion\scripts\convert-encoding.bat "<arquivo>"
  ```

- **Windows-1251** — os scripts das skills são fixos em CP1252 e **não** servem para este caso.

  Linux/macOS:

  ```bash
  tmp=$(mktemp) && sed '1s/^\xEF\xBB\xBF//' "<arquivo>" | iconv -f UTF-8 -t CP1251 > "$tmp" && cat "$tmp" > "<arquivo>"; rm -f "$tmp"
  ```

  Windows (PowerShell):

  ```powershell
  $p = "<arquivo>"; $t = [IO.File]::ReadAllText($p, [Text.Encoding]::UTF8); [IO.File]::WriteAllBytes($p, [Text.Encoding]::GetEncoding(1251).GetBytes($t))
  ```

  Windows (CMD), se o PowerShell não funcionar:

  ```cmd
  powershell -NoProfile -ExecutionPolicy Bypass -Command "$p='<arquivo>'; $t=[IO.File]::ReadAllText($p,[Text.Encoding]::UTF8); [IO.File]::WriteAllBytes($p,[Text.Encoding]::GetEncoding(1251).GetBytes($t))"
  ```

  `ReadAllText` com UTF-8 já descarta o BOM; `WriteAllBytes` grava sem BOM.

**Arquivo existente com bytes acima de `0x7F`** (acentos, cirílico) — **nunca** use `str_replace`/`fs_write` direto sobre ele: a ferramenta decodifica como UTF-8 e troca, no arquivo inteiro, cada caractere especial por `U+FFFD` de forma irreversível.

- **Windows-1252** — use a skill `cp1252-safe-source-edit`.
  - Linux/macOS: `bash .kiro/skills/cp1252-safe-source-edit/scripts/safe-replace.sh "<arquivo>" old.txt new.txt 1`
  - Windows (PowerShell): `powershell -NoProfile -File .kiro\skills\cp1252-safe-source-edit\scripts\safe-replace.ps1 -Path "<arquivo>" -OldFile old.txt -NewFile new.txt -ExpectedCount 1`
  - Windows (CMD), se o PowerShell não funcionar (ex.: `.ps1` bloqueado):

    ```cmd
    powershell -NoProfile -ExecutionPolicy Bypass -File .kiro\skills\cp1252-safe-source-edit\scripts\safe-replace.ps1 -Path "<arquivo>" -OldFile old.txt -NewFile new.txt -ExpectedCount 1
    ```

  Os arquivos auxiliares `old.txt`/`new.txt` são temporários: apague-os ao terminar.

- **Windows-1251** — faça o round-trip explícito: converta para UTF-8, edite com a ferramenta e converta de volta **antes de qualquer outra ação**.

  Linux/macOS:

  ```bash
  # 1. CP1251 -> UTF-8 (in-place)
  tmp=$(mktemp) && iconv -f CP1251 -t UTF-8 "<arquivo>" > "$tmp" && cat "$tmp" > "<arquivo>"; rm -f "$tmp"
  # 2. editar com str_replace
  # 3. UTF-8 -> CP1251 (in-place)
  tmp=$(mktemp) && iconv -f UTF-8 -t CP1251 "<arquivo>" > "$tmp" && cat "$tmp" > "<arquivo>"; rm -f "$tmp"
  ```

  Windows (PowerShell):

  ```powershell
  # 1. CP1251 -> UTF-8 (in-place, sem BOM)
  $p = "<arquivo>"; $t = [IO.File]::ReadAllText($p, [Text.Encoding]::GetEncoding(1251)); [IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($false)))
  # 2. editar com str_replace
  # 3. UTF-8 -> CP1251 (in-place)
  $p = "<arquivo>"; $t = [IO.File]::ReadAllText($p, [Text.Encoding]::UTF8); [IO.File]::WriteAllBytes($p, [Text.Encoding]::GetEncoding(1251).GetBytes($t))
  ```

  Windows (CMD), se o PowerShell não funcionar:

  ```cmd
  REM 1. CP1251 -> UTF-8 (in-place, sem BOM)
  powershell -NoProfile -ExecutionPolicy Bypass -Command "$p='<arquivo>'; $t=[IO.File]::ReadAllText($p,[Text.Encoding]::GetEncoding(1251)); [IO.File]::WriteAllText($p,$t,(New-Object Text.UTF8Encoding($false)))"
  REM 2. editar com str_replace
  REM 3. UTF-8 -> CP1251 (in-place)
  powershell -NoProfile -ExecutionPolicy Bypass -Command "$p='<arquivo>'; $t=[IO.File]::ReadAllText($p,[Text.Encoding]::UTF8); [IO.File]::WriteAllBytes($p,[Text.Encoding]::GetEncoding(1251).GetBytes($t))"
  ```

No CMD, caminhos com `%` precisam ser escapados como `%%` dentro de `.bat`. Use aspas simples dentro do `-Command` e aspas duplas em volta dele, como nos exemplos.

Arquivo 100% ASCII é compatível com os dois codepages; mesmo assim, rode a conversão em arquivos novos (o script da skill apenas o ignora).

### Verificação antes de concluir

- `file --mime-encoding "<arquivo>"` **não** pode retornar `utf-8` quando o arquivo tiver caracteres não-ASCII.
- Para fonte existente, `git diff --stat -- "<arquivo>"` deve mostrar só as linhas pretendidas. Diff em massa indica corrupção de encoding: reverta com `git checkout -- "<arquivo>"` e refaça pelo caminho seguro.
- Nenhum artefato pode sobrar: sem `.bak`, `.orig`, `.utf8`, `.cp1252`, `.tmp`, cópias ou renomeações.
- Sem BOM no início do arquivo.
- Só checar sintaxe/compilar **depois** da conversão. Compilar um fonte ainda em UTF-8 não prova nada.

Este requisito vale apenas para as extensões AdvPL/TLPP desta steering. Arquivos `.md`, `.json`, `.py`, `.yaml` e afins permanecem em UTF-8.
